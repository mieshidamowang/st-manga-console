# 漫画台插件版0.1版本

MIT 开源的 SillyTavern 扩展。用任意正文预设写完故事，再使用独立的 OpenAI 兼容模型编写漫画分镜，通过 NovelAI 兼容生图接口生成漫画并追加到原楼层。

**本仓库现在是完整可安装的 0.1.0 版本。** 生图引擎和漫画规则为独立编写，不包含此前未授权的原预设代码、原提示词或配套素材。

## 安装

1. 在 SillyTavern 打开 **扩展 → 安装扩展**。
2. 粘贴 `https://github.com/mieshidamowang/st-manga-console` 并安装。
3. 刷新酒馆，点击右下角 **漫画台 0.1**，或扩展设置中的 **打开漫画台**。

无需 Node 构建、npm 安装或服务器插件。基础功能使用酒馆原生聊天 API；世界书读取可选依赖酒馆助手，数据库上下文可选依赖提供 AutoCardUpdaterAPI 的数据库插件。开发验证基于 SillyTavern 1.18.0 的 getContext 接口和现代 Chromium/Edge。

若你已手动安装旧的非 Git 漫画台目录，同名安装可能提示已存在。先备份旧扩展目录，再通过酒馆卸载旧版后安装；不要同时开启两个版本的自动生图。0.1 使用独立设置和聊天元数据，不自动读取旧版提示词、Key 或私有缓存。

## 第一次使用

1. **编剧**：填写 OpenAI 兼容 API 基础地址（包含 `/v1` 等前缀）、API Key、模型 ID。支持 Gemini 的 OpenAI 兼容服务，也可手动填写其他兼容模型。服务商不支持 tools 时关闭“工具传输”。
2. **生图连接**：填写 NovelAI 或兼容服务的基础地址、Key 和模型 ID。默认地址 `https://image.novelai.net`，默认模型 `nai-diffusion-4-5-full`；可按服务商支持情况更改。请求使用 `/ai/generate-image` 协议，不是 OpenAI images 协议。
3. 两类 Key 分开配置。点击各自“保存连接”后保存在当前酒馆用户文件；不点击保存则仅在当前页面保留。
4. 打开角色聊天，正常生成小说正文。
5. 在 **编剧** 选择最近 N 层或指定楼层范围，先点 **预览发送内容** 检查正文与上下文。
6. 点击 **正文转漫画并生图**。模型建议建立主要角色 / 服装档案时会弹窗，检查或修改 Tag，保存或本次跳过。

调用编剧和生图服务可能消耗相应 API 额度。预览、编辑设置和查看历史不会请求生图。本项目不附带 Key 或免费额度；远程接口需要支持浏览器 CORS 直连。

## 功能

- 独立编剧连接、模型列表、超时与取消，普通文本或工具调用返回。
- 正文标签提取、排除思考/状态内容、最近 N 层或自定义范围；楼层从 0 开始。
- 可选角色卡、用户设定、数据库表格和世界书上下文。世界书读取全部绑定的启用条目，不模拟原生触发器。
- 页数、画格数、黑白/全彩、对白语言、阅读顺序、留白、画风，以及可编辑的原创规则。
- 角色中英文名、别名、正背面外观、SFW/NSFW 上下半身 Tag、服装归属和默认服装。按人物引用选择 Tag，不混入整页背景提示词。
- 模型判断新主要角色 / 服装后预填候选并弹窗，确认才保存；不是正文出现任意新人名就立即建档。重复已有名称不提示。
- 自动编剧生图默认关闭，可在控制台或编剧页开启。
- 新图片保留原正文并追加图片区，更新当前 swipe；成功页跳过重复请求，支持整层和单页重画。失败不自动重试收费请求。
- PNG / ZIP 图片响应解析（存储或 Deflate 压缩，校验 ZIP CRC）、上传酒馆图片目录、最近 100 张图片历史、预览和下载。
- 顺序生图；取消、切换聊天或正文变化后拒绝过期回填。

## 保存位置与隐私

- 普通设置、角色库和历史索引：`extensionSettings.mangaConsoleOpen01`。
- 分镜和当前页图片：聊天元数据 `mangaConsoleOpenPlans01`。
- 编剧连接：当前用户 `manga-open-director-connection.json`。
- 生图连接：当前用户 `manga-open-image-connection.json`。
- 图片：酒馆用户图片目录的 `manga-console-open` 子目录。

Key 文件使用酒馆用户文件存储，不是加密保险库；请保护酒馆账号及备份。提示词/角色库导出不包含 Key。提交问题时不要附上 Key、私有聊天或连接文件。

## 范围与限制

这是独立实现的首个公开版本，不是原预设全部高级模块的逐项复刻。没有包含原防截断脚本、数据库模板缝合、剧情调度、MOBI 导出、账号轮换或参考照片管理。图片历史是已保存服务器图片的索引，不是离线图片数据库。

模型输出质量和页数/文字准确性取决于所选模型；每页最多六个人物实例。人物调用使用分镜中的 `[[cast:姓名|front或back|upper或full|sfw或nsfw|服装名]]`，旧分镜没有引用时可按人物编号或人名关键词匹配。库变化不会自动重画已有图片。生图接口目前面向 NovelAI V4/V4.5 风格请求；不承诺任何代理或其他图像模型都兼容。

## 开发与测试

无需构建即可加载。使用 Node.js 22+ 执行：

```sh
npm test
```

单元测试覆盖协议、参数、角色/服装分离、ZIP 解压校验、上下文提取和安装文件完整性。开发期间另用无头 Edge 和模拟的酒馆/OpenAI/NovelAI 服务验证完整流程、手机弹窗、取消及跨聊天保护。没有使用真实 Key 进行收费生成，第三方服务可用性和绘图质量需用户实测。
